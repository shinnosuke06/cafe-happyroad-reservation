# cafe ハッピーロード 予約管理システム

cafe ハッピーロードの予約を受け付けて管理するWebアプリです。
お客様がスマホから予約できる **予約ページ** と、スタッフが予約を確認・登録する **管理画面（予約台帳）** があります。

- 追加のライブラリは不要です（Node.js だけで動きます）
- データは Node.js に組み込みの SQLite に保存します

## できること

### お客様（予約ページ `/`）

- 日付・人数を選ぶと、30分ごとの空き状況（◯／×）が表示される
- 時間を選んで、お名前・電話番号（必須）、メール・ご要望（任意）を入力して予約
- 予約すると6文字の **予約番号** が表示される
- 予約番号と電話番号で、予約の確認・キャンセルができる
- 定休日・臨時休業日、受付期間外、当日の締切を過ぎた時間は選べない
- 電話番号は全角で入力しても大丈夫

### スタッフ（管理画面 `/admin`）

- パスワードでログイン（5回まちがえると15分ロック）
- **予約台帳**：日ごとの予約を「タイムライン」（テーブル×時間）と「リスト」で表示
  - 予約組数・人数・来店済・キャンセルの集計
  - タイムラインの空いている所をタップすると、そのテーブルと時間で予約を追加
  - 「来店」ボタンで来店済にする
  - 予約の変更（日時・人数・テーブル・状態など）と削除
  - Web予約は1分ごとに自動で反映
- **電話予約・飛び込み客の登録**：テーブルは「自動」でも、指定してもOK。重なる予約があれば「◯◯様の予約が入っています」と教えてくれる
- **検索**：お名前・電話番号の一部・予約番号で過去の予約も探せる
- **設定**
  - 店名、お店の電話番号、営業時間、予約の間隔、1組の利用時間
  - Web予約の最大人数、何日先まで受け付けるか、当日は何分前まで受け付けるか
  - 定休日（曜日）、臨時休業日
  - テーブル（席）の追加・名前と席数の変更・休止・削除

### テーブルの割り当てルール

Web予約は、**人数が座れる中で一番小さい空きテーブル** に自動で入ります（2名なら2人席から、5名ならソファ6人席）。
利用時間が重ならなければ、同じテーブルに続けて予約が入ります。

初期のテーブル：窓際1（2席）・窓際2（2席）・テーブル3（4席）・テーブル4（4席）・テラス5（4席）・ソファ6（6席）

## 起動のしかた

Node.js **22.13 以上** が必要です。

```bash
git clone https://github.com/shinnosuke06/cafe-happyroad-reservation.git
cd cafe-happyroad-reservation
ADMIN_PASSWORD=好きなパスワード npm start
```

- 予約ページ：http://localhost:3000/
- 管理画面：http://localhost:3000/admin

> `ADMIN_PASSWORD` を設定しないと、仮のパスワード `happyroad` になります。お店で使う前に必ず設定してください。

### 設定できる環境変数

| 名前 | 内容 | 初期値 |
| --- | --- | --- |
| `ADMIN_PASSWORD` | 管理画面のパスワード | `happyroad`（仮） |
| `PORT` | 待ち受けるポート | `3000` |
| `HOST` | 待ち受けるアドレス | `0.0.0.0` |
| `DB_PATH` | データベースファイルの場所 | `data/happyroad.db` |
| `STORE_TIMEZONE` | お店のタイムゾーン（「今日」の判定に使う） | `Asia/Tokyo` |

## データとバックアップ

予約・設定・テーブルはすべて `data/happyroad.db` の1ファイルに入っています。
このファイルをコピーすればバックアップになります（`data/` は Git には入りません）。

## インターネットに公開するとき

このアプリはサーバーで動くので、GitHub Pages では公開できません。次のような場所で動かしてください。

- VPS（さくらのVPS、ConoHa など）に Node.js を入れて `npm start`
- Render・Railway・Fly.io など、**ディスクを保存できる** ホスティング（`DB_PATH` を保存されるディスクに向ける）

公開するときは HTTPS にしてください（nginx や Caddy を前に置く、またはホスティングの HTTPS 機能を使う）。
HTTPS で動いていると、ログインの Cookie に自動で `Secure` が付きます。

## 開発

```bash
npm run dev   # ファイルを変えると自動で再起動
npm test      # テスト（予約ルールと API）
```

### フォルダ構成

```

  reserve.js

  admin.js
  common.js        共通の部品

test/              テスト
```

### API

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/info` | 店名・営業時間・予約できる期間 |
| GET | `/api/availability?date=&party=` | その日の空き状況 |
| POST | `/api/reservations` | Web予約 |
| POST | `/api/reservations/lookup` | 予約番号＋電話番号で確認 |
| POST | `/api/reservations/cancel` | 予約番号＋電話番号でキャンセル |
| POST | `/api/admin/login` / `logout` | スタッフのログイン・ログアウト |
| GET | `/api/admin/reservations?date=` / `?q=` | 日ごとの予約一覧／検索 |
| POST・PATCH・DELETE | `/api/admin/reservations[/:id]` | 予約の登録・変更・削除 |
| GET・PUT | `/api/admin/settings` | 設定の取得・保存 |
| POST・PATCH・DELETE | `/api/admin/tables[/:id]` | テーブルの追加・変更・削除 |
| POST・DELETE | `/api/admin/closures[/:date]` | 臨時休業日の追加・取消 |

`/api/admin/` で始まる API はログインが必要です。
